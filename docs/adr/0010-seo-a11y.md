# ADR-0010: SEO and accessibility — developer duty; sitemap/robots in the framework

- Status: Accepted
- Date: 2026-10-10

## Context

Company sites (0009) need SEO and a11y like the driving-school project (meta, structure, semantic modules). Neither should be “forgotten” later. The kernel cannot enforce copy, alt text, or contrast of a customer component. **Sitemap and robots.txt** are machine-readable, central artifacts — the framework can generate them from routes and published CMS pages.

PHP views (ADR-0012) send HTML in the first response — closer to classic SSR than a client-only SPA. Sitemap/robots still belong in the framework.

A JS SPA would need a new ADR; it is not the current view layer.

## Alternatives

1. Leave everything to the developer — sitemaps get forgotten.
2. Framework enforces WCAG and meta in every block — unrealistic, too early.
3. **Split:** a11y and content SEO = developer (and later first-party blocks as a good example). **robots.txt** and **sitemap.xml** = framework feature (generatable) once public URLs exist.

## Decision

Option 3. Implement **later**, contract **now**.

**Framework (can/should generate):**

- `GET /robots.txt` — allow indexing the public site, `Disallow` admin/API per config.
- `GET /sitemap.xml` — from known public routes plus published CMS pages (`slug`, `updated_at` from 0009). Hook/config for extra URLs.
- No guarantee of Google ranking.

**Developer (and CMS blocks):**

- Semantics, keyboard, labels, contrast, `alt` — in components, not magically in the PHP router.
- Page meta (title, description, canonical, JSON-LD): fields on the page document; PHP layouts/`render()` output them. The framework can provide fields, not the copy.

First-party blocks in the CMS flavor should not be worse on a11y than the driving-school modules; that is the quality bar (0008), not a kernel mandate for third-party components.

## Consequences

- A sitemap is useful only once pages or static public routes exist.
- Admin routes do not belong in the sitemap.
- If SEO still fails, fix titles, semantics, and sitemap — not a second JS renderer, unless a new ADR says so.
